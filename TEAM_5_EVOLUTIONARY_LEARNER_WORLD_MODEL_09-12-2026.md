## 3. Process — evaluate → update world model → propose explorations

```text
Team 3 hotfix outcomes ──┐
                         ├──► evaluate signals
Team 4 Go/No-Go records ─┘         │
                                   ▼
                    Metric Sentinel enrich (hard + soft)
                                   │
                                   ▼
                         update world model
                                   │
                                   ▼
                    propose exploratory actions
                                   │
                                   ▼
              Strategy Architect rank (commercial priority)
                                   │
                                   ▼
                     human / CEO gate (veto risky)
                                   │
                                   ▼
                    Team 1 Discovery → modular blueprints
```

### 3.1 Evaluate

1. Aggregate Support + Gatekeeper outcomes for the period (manual ok).  
2. Drop incomplete records (no module id / no veto reason / no failure tags)—or mark them **low-confidence**.  
3. Attach Metric Sentinel context; flag partial telemetry explicitly.  
4. Score pattern strength (recurrence, MTTR, veto theme frequency, post-deploy errors).

### 3.2 Update world model

Revise beliefs about:

* **Fragile modules** — units that repeatedly need hotfixes or rollbacks.  
* **Failed blueprint assumptions** — contracts that Gatekeepers keep vetoing or Support keeps patching around.  
* **Repeated governance blocks** — security/compliance themes that stall generations.  
* **ROI-correlated patterns** — pain that also destroys adoption / soft benefits vs noise.

World model is a **documented belief set** today (briefs / tables)—not an in-repo RL store.

### 3.3 Propose explorations

Candidate exploratory actions (modular only):

* Refactor or split a brittle MCP / hook / skill / extension.  
* New MCP/hook surfaces that remove Support workarounds.  
* Retirement of low-value or high-fragility units.  
* Process redesign around agentic capabilities (strategic reinvention)—not ticket automation theater.

Strategy Architect ranks commercially; Learner supplies evidence packs.

## 5. Human veto on risky explorations

| Risk class | Default gate |
|------------|--------------|
| Ethics / irreversible product spine change | **Human CEO / Admin required** |
| Broad process redesign / market pivot | CEO accept / reject / defer |
| High blast-radius refactor across many modules | Humans (ops/eng) + CEO as needed |
| Narrow modular exploration with inspectable metrics | May proceed after recorded human acceptance |

### 5.1 Non-negotiable

* Team 5 **advises**; it does not silently pivot.  
* Risky explorations require **explicit human veto power**—accept, reject, or defer.  
* Soft-benefit and ROI claims attached to proposals must be inspectable.  
* Technical Go from Team 4 does **not** authorize strategic exploration without the CEO gate when ethics/strategy is involved.
