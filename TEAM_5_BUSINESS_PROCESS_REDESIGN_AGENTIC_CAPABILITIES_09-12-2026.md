## 2. When Team 5 proposes redesign

| Signal | Why redesign may beat more patches |
|--------|------------------------------------|
| Recurring Team 3 hotfixes on the same workflow seam | Blueprint / process debt |
| High cycle time despite Go ships | Process, not only code |
| Soft-benefit regression (burnout / trust) | Humans drowning in agent-adjacent thrash |
| Market / Strategy Architect pivot | Competitor workflows obsolete the current path |
| Metric Sentinel ROI stall | Automation without process change yields no value |

---

## 3. Redesign proposal schema (CEO + Team 1)

| Field | Required content |
|-------|------------------|
| **Process name / boundary** | What workflow is in scope |
| **As-is pain** | Evidence (incidents, cycle time, soft claims with method) |
| **To-be design** | Steps agents own vs humans own |
| **Modular targets** | MCP / hook / skill / extension list |
| **Hard KPI deltas** | Expected ROI / cycle / adoption / error changes |
| **Soft-benefit deltas** | Satisfaction / burnout / trust — method labeled |
| **Risks & ethics flags** | Irreversible lock-in, surveillance, unfair automation |
| **CEO ask** | Accept / Reject / Defer / Halt |
| **If Accepted** | Hand to Team 1 modular blueprint packet |

The generic Accept / Reject / Defer / Halt CEO-ask gate itself is the same schema canonicalized in [`TEAM_5_STRATEGY_ARCHITECT_MARKET_AND_ROADMAP_09-12-2026.md`](TEAM_5_STRATEGY_ARCHITECT_MARKET_AND_ROADMAP_09-12-2026.md) §4.2; the process-specific fields above (process boundary, as-is pain, to-be design, KPI/soft-benefit deltas) are this doc's own distinct "agentic capabilities" redesign-proposal framing.

CEO gate
