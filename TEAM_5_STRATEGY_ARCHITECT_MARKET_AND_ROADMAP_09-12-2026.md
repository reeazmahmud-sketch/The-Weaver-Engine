## 3. Competitor & market monitoring

### 3.1 Signal classes

| Signal | Why Architect cares |
|--------|---------------------|
| Competitor feature / pricing moves | Threat or opportunity for modular bets |
| Market trend / regulation shifts | Forced roadmap pivots; compliance-adjacent strategy |
| Research / standards frameworks | Discovery inputs Team 1 already uses—Architect aligns commercial priority |
| Customer / operator demand themes | Adoption and soft-benefit alignment |
| Internal Sentinel trends | Whether our ships create value vs competitors’ narrative |

Until coded, signals may be **manual research notes** with source URLs / dates. Label confidence (high / medium / low).

### 3.2 Monitoring cadence (protocol)

1. Collect external signals for the period (manual ok).  
2. Diff against current roadmap / modular capability map.  
3. Attach Metric Sentinel post-Go context where relevant (label **partial** if logging-only).  
4. Produce a short market brief + ranked gaps.  
5. Feed gaps into roadmap pivot options (§4) and Learner ranking (§5).

## 4. Roadmap pivots

Strategy Architect recommends **options**, not a single silent decision:

| Pivot class | Example | Modular preference |
|-------------|---------|--------------------|
| **New feature / surface** | New MCP / hook / skill / extension family | Replaceable unit specs for Team 1 |
| **Retirement** | Low-ROI / high-burnout module family | Explicit sunset + migration note |
| **Capability bet** | Long-horizon agentic platform investment | Multi-horizon brief (see long-term strategy) |
| **Process redesign** | Workflow reinvented around agents | See business process redesign companion |
| **Hold / defer** | Wait for more Sentinel or market evidence | Revisit condition recorded |

### 4.1 Strategic reinvention lens

Pivots should advance **strategic reinvention**—redesign how work happens with agentic capabilities—not only automate yesterday’s tickets. Contrast with Team 4: technical **Go** clears a ship; Architect asks whether the **roadmap** should change because of markets + value proof.

### 4.2 Minimum option fields (CEO pack)

1. Decision asked (Accept / Reject / Defer / Halt)  
2. Market / competitor evidence summary (sources + date)  
3. Metric Sentinel hard + soft context (or **partial**)  
4. ≥2 options when strategy pivot; each with modular target shape  
5. Trade-offs (value, risk, time-to-value, blast radius)  
6. Team 4 technical status contrast (if a related ship exists)  
7. Recommended next team if Accepted (usually Team 1 Discovery)

## 5. Ranking Evolutionary Learner explorations

Learner proposes explorations from Support / Gatekeeper outcomes. Architect **prioritizes commercially**:

| Rank factor | Prefer higher when… |
|-------------|----------------------|
| Market urgency | Competitor / regulation forces a response window |
| ROI / soft-benefit leverage | Sentinel shows material value at stake |
| Fragility / recurrence | Learner evidence shows systemic pain |
| Modular blast radius | Smaller, replaceable units beat monolith rewrites |
| CEO priority alignment | Matches stated investment / ethics posture |

Output: prioritized queue with rationale; **risky** items still require human veto (Accept / Reject / Defer / Halt) before Team 1.
