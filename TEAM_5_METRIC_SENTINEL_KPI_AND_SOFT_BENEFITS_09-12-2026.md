## 1. Mission / production monitoring

### 1.1 Mission

**Quantify whether the agentic system is creating real value** in production—after Governance has approved ship—not during pre-gate drafts.

| Input | Process | Output |
|-------|---------|--------|
| Team 4 Go / Conditional Go + deploy notify (stage ⑦) | Open post-deploy value window | Module-scoped scoring period |
| Ops telemetry + Support/Gatekeeper outcomes | Hard KPI scoring | ROI / cycle / adoption / error snapshots |
| Surveys, pulse notes, on-call load, override rates | Soft-benefit scoring | Inspectable human-impact claims |
| Combined hard + soft packs | Trend / alert drafting | Inputs for Strategy Architect, Evolutionary Learner, CEO |

### 1.2 Production monitoring stance

* Metric Sentinel is a **Value Optimization** organ—not CI/CD, not Support hotfix authoring, not Discovery.  
* It monitors **shipped modular units** (MCP / hook / skill / extension ids) and generation-level outcomes.  
* It produces **rolling snapshots**, **trend views**, and **alerts**—consumers decide strategy; Sentinel does not silently pivot.  
* Soft benefits are **first-class**, not vanity garnish on ROI.

### 1.3 Explicit non-goals (mission)

* Do **not** treat Team 4 technical Go as proof of ongoing value.  
* Do **not** score “value created” for pure **No-Go** ships (vetoes still feed Evolutionary Learner as governance friction).  
* Do **not** equate `uptime_dashboard.txt` with a full Sentinel scorecard.  
* Do **not** implement Docker or claim the scoring engine is live in Weaver code.

## 2. Quantitative KPIs table

Score **after** Team 4 technical Go (or material Conditional Go) + deploy + **⑦ Notify Team 5**. Attribute to **module id** / ship package where possible. **ROI and related formulas are not coded**—use manual/CEO briefs until an engine exists.

| KPI | Intent | Attribute to | Suggested evidence / notes | Weaver today |
|-----|--------|--------------|----------------------------|--------------|
| **ROI** | Value created vs cost of shipped modular unit(s) | Module id / ship package | Cost of build+gate+run vs attributable benefit; period window post-Go | **Not coded** — CEO/manual pack |
| **Time saved** | Human hours avoided by agentic path vs baseline | Workflow / module | Before/after time studies; ticket handle time; assist vs grind | **Not coded** |
| **Cycle time** | Discovery→ship latency; hotfix MTTR; gate dwell | Generation / path type | Steady-state vs emergency path; gate queue time | **Partial** proxies only (ops timestamps if logged) |
| **Adoption** | Real use of shipped capability | Module id | Routes, skill hits, MCP calls, active users | **Not coded** (no adoption funnel) |
| **Revenue uplift** | Attributable revenue or cost avoidance | Product / feature family | Finance-tagged uplift; avoid double-count | **Not coded** |
| **Error reduction** | Post-deploy error rate vs baseline | Module id | Error rate, recurrence, rollback frequency | **Partial** — task/error slices via logging substrate if present |
| **Deploy success rate** | Go ships that stay healthy without rollback | Gatekeeper period | Healthy dwell vs rollback after Go | **Not coded** (no CI/CD control plane) |
| **Hotfix frequency** | Patches per module / period | Module id | Pair with Team 3 hotfix tags | **Not coded** (docs/signals manual) |

### 2.1 Scoring rules

1. **Post-Go only** for “value created” claims.  
2. **Rollbacks after Go** are first-class **negative** signals (cycle time + errors + ROI).  
3. Prefer **module-id attribution**; refuse anonymous “system got better” claims.  
4. Humans/CEO may **reject** KPIs that game the system (inspectability required).  
5. Partial telemetry must be labeled **partial**—never presented as full ROI.

### 2.2 Example post-Go scorecard skeleton (manual)

```text
module_id:          <mcp|hook|skill|extension id>
ship_package:       <generation / release tag>
go_decision:        Go | Conditional Go
value_window:       <start ISO> → <end ISO>
roi:                <manual> | pending
time_saved_hours:   <manual> | pending
cycle_time:         discovery→ship / MTTR / gate_dwell
adoption:           routes | skill_hits | mcp_calls | users
errors:             rate_vs_baseline | rollbacks | recurrence
soft_benefits:      see §3 (survey/proxy refs)
telemetry_label:    full | partial (logging_suite only)
```

## 3. Soft benefits (satisfaction, burnout) + measurement notes

Soft benefits justify continued investment and guide **strategic reinvention** alongside hard ROI. They are **not** vanity dashboards. Claims must be inspectable; humans may reject gamed metrics.

| Soft benefit | What “good” looks like | Measurement notes (manual OK) | Automated in Weaver? |
|--------------|------------------------|-------------------------------|----------------------|
| **Employee satisfaction** | Operators prefer agentic assist over grind | Pulse / survey notes; preference vs prior workflow; qualitative ops feedback | **No** |
| **Reduced burnout** | Fewer after-hours fire drills; lower MTTR stress | On-call load, incident volume, after-hours pages, hotspot recurrence | **No** (incident volume may use partial ops signals) |
| **Clearer decision latency** | Faster, documented choices with options packs | Time-to-decision logs; presence of ranked options before CEO gate | **No** |
| **Trust in automation** | Humans accept agent drafts without rework churn | Override rate, rework rate, silent discard rate of agent drafts | **No** |

### 3.1 Soft-benefit rules

* Soft claims **travel with** hard KPI packs to Strategy Architect / Learner / CEO—never alone as “success.”  
* Prefer **named evidence artifacts** (survey id, on-call week, override log excerpt) over slogans.  
* Burnout relief that coincides with **rising hotfix frequency** is suspect—cross-check §2.  
* CEO / humans retain veto on soft metrics that feel gamed.

### 3.2 Why soft benefits matter for Team 5

Strategic reinvention (process redesign around agentic capabilities) fails if humans hate the new path. Metric Sentinel therefore treats satisfaction and burnout as **investment criteria**, not HR garnish—see [`TEAM_5_BUSINESS_PROCESS_REDESIGN_09-12-2026.md`](TEAM_5_BUSINESS_PROCESS_REDESIGN_09-12-2026.md) and [`TEAM_5_CORE_OBJECTIVE_STRATEGIC_REINVENTION_09-12-2026.md`](TEAM_5_CORE_OBJECTIVE_STRATEGIC_REINVENTION_09-12-2026.md).

## 5. Post Team-4 Go tracking

### 5.1 Trigger

Once Team 4 records a technical **Go** (or material **Conditional Go**), completes deploy stage ⑥, then **⑦ Notify Team 5** per [`TEAM_4_CICD_DEPLOYMENT_AND_GO_NO_GO_09-12-2026.md`](TEAM_4_CICD_DEPLOYMENT_AND_GO_NO_GO_09-12-2026.md), Metric Sentinel opens a **post-deploy value window**.

```text
Team 4 ⑤ Go/No-Go ──► ⑥ Deploy ──► ⑦ Notify Team 5
                                         │
                                         ▼
                              Metric Sentinel (post-deploy)
                         ROI · time saved · cycle · adoption
                         errors · deploy health · hotfix rate
                         + soft benefits (§3)
                                         │
                                         ▼
                    Strategy Architect + Evolutionary Learner
                                         │
                                         ▼
                                  CEO insight pack
```

### 5.2 What to track in the value window

| Track | Post-Go measure | Notes |
|-------|-----------------|-------|
| **ROI** | Value vs cost of shipped unit(s) | Manual until formulas coded |
| **Cycle time** | Discovery→ship; hotfix MTTR; gate dwell | Compare steady-state vs emergency |
| **Adoption** | Routes / skill hits / MCP calls / users | Module-id attribution |
| **Errors** | Error rate, rollback, recurrence | Pair with Team 3 hotfix tags |
| **Soft benefits** | Satisfaction, burnout, decision latency, trust | Inspectable claims only |

### 5.3 Contrast with Team 4 Go/No-Go

| Gate | Owner | Question |
|------|-------|----------|
| **Technical Go/No-Go** | Team 4 Gatekeepers | Is it safe/compliant enough to ship? |
| **Ongoing value** | Team 5 Metric Sentinel (+ CEO) | Did shipping create hard + soft value worth keeping / reinventing / retiring? |

Authority detail: [`TEAM_4_GO_NO_GO_AUTHORITY_09-12-2026.md`](TEAM_4_GO_NO_GO_AUTHORITY_09-12-2026.md). Technical Go **never** replaces CEO ethics/strategy halt.

### 5.4 No-Go and rollback handling

* **No-Go:** do not claim value created; still forward veto reasons to Evolutionary Learner.  
* **Rollback after Go:** negative Sentinel signal; enrich Learner fragility beliefs.  
* **Conditional Go:** score only the scoped conditions that actually shipped; label residual risk.
